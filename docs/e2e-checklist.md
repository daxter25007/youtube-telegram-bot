# E2E-чеклист: полный обход всех источников

Ручной сценарий проверки бота на живых ссылках. Ссылки проверены
2026-11-09 (oEmbed / с prod-VPS / по истории таблицы `downloads`); публичные
ссылки со временем умирают — при падении теста сначала проверьте саму ссылку,
потом бот. Мёртвую ссылку заменяйте свежей того же формата.

## Предусловия

- бот запущен на prod (VPS) с включённым Cobalt;
- тестовый Telegram-аккаунт не занят другой загрузкой (лимит 1 активная на пользователя);
- под рукой аккаунты TikTok / Instagram / Pinterest / VK для генерации коротких ссылок.

## Основной обход

Порядок: сначала быстрые smoke-ссылки, потом тяжёлые. Для каждой ссылки:
бот присылает карточку метаданных → выбрать вариант → дождаться файла →
проверить, что видео стримится в Telegram (`supports_streaming`), а не уходит
документом без нужды.

## Поведенческие проверки

- **Кэш `file_id`**: отправить 1.1 повторно — второй ответ приходит быстро,
  без нового скачивания (в статистике — cache hit).
- **Очередь**: запустить 1.4 и сразу 6.3 — вторая ждёт, прогресс не смешивается.
- **Fallback Cobalt → yt-dlp**: при заглушенном Cobalt 3.x/4.x/5.x всё равно
  качаются (тот же общий таймаут).
- **Честный прогресс**: во время скачивания статус показывает
  `⬇️ N% · X из Y МБ · Z КБ/с` — байты растут даже когда процент «стоит»
  (медленная загрузка отличима от зависшей).
- **Отмена `/cancel`**: запустить тяжёлую загрузку, отправить `/cancel` —
  бот отвечает «🚫 Отменяю загрузку…», прогресс-сообщение меняется на
  «🚫 Загрузка отменена.», в БД статус `cancelled`, слот пользователя
  освобождается (следующая ссылка принимается). `/cancel` без активной
  загрузки отвечает «У вас нет активной загрузки.»

## Стресс-кейс (ручной, не в автопрогоне)

- Часовое видео Rutube `https://rutube.ru/video/2434c157d371b09649e1464a9f59cce0/`
  на 144p качается 10+ минут (~100–150 КБ/с с польского VPS) и всё это время
  держит единственный слот пользователя — проверять вместе с `/cancel`.

## Известные особенности prod

- Веб-страницы VK (`vkvideo.ru`, `vk.com`) на curl без cookies отдают 302 на
  логин — и с VPS, и из РФ. Это не влияет на бот: yt-dlp-экстрактор ходит
  другими эндпоинтами, клипы и видео качались на prod без cookies.
- Cobalt в Docker network недоступен снаружи — проверять его состояние только
  изнутри (`docker compose exec bot …`).
- Провал в истории prod: YouTube `watch?v=rXfXa8nLLVA` падал (вероятно
  PO-token/возрастные ограничения) — годится как устойчивость-тест, не как
  обязательный пункт.
